fdmnes-xas-pipelineA dependency-free (stdlib-only) Python package for automating FDMNES X-rayabsorption spectroscopy (XANES/EXAFS) calculations. It takes a structure(a CIF for a K-edge/crystal job, or an `.xyz` molecule for an L-edge job),generates the FDMNES input file, runs FDMNES itself (sequentially or viaMPI), validates the output against FDMNES's own error-reportingconventions, and -- once you have an experimental spectrum -- scores thecomputed spectrum against it (Pearson correlation, R-factor, automaticenergy alignment) across one job or an entire batch at once.Workflow![fdmnes_pipeline workflow: structure -> generate -> run -> validate -> compare](docs/workflow.svg)FeaturesTwo structure input modes: K-edge jobs from a CIF (FDMNES's`Cif_file` keyword) and L-edge jobs from a plain `.xyz` file (FDMNES's`Molecule` keyword, with `Edge`/`TDDFT`/`Spinorbit`/`Vmax`/`Estart`/`Overad`support) -- the same `JobSpec`/`ProtocolSettings` model handles both, anda K-edge job's output is unaffected by any of the L-edge-only fields.Per-site absorber selection: run a separate calculation for eachdistinct metal environment in a structure (`absorber_mode`/`absorber_index`),instead of treating every atom of that element as equivalent.Batch configs in plain JSON: one shared `protocol` plus a list of`jobs`, each able to override individual settings with`protocol_overrides` -- no YAML dependency, see `examples/jobs.json`.Automated running: writes `fdmfile.txt` next to the FDMNESexecutable (per FDMNES's own requirement that it live there), launchesFDMNES sequentially or under `mpirun`, with a configurable per-jobtimeout.Output validation: flags a job as `SUCCESS`/`WARNING`/`FAILED` basedon FDMNES's own crash signal (`fdmnes_error.txt`), missing/empty outputfiles, and a few heuristics for a `_conv.txt` that parsed but looksnumerically off.Experimental benchmarking: normalizes, auto-aligns (or lets you seta fixed shift), and scores a computed spectrum against an experimentalone, with an optional overlay plot and CSV export of the aligned data-- one job at a time (`compare`) or across a whole batch, matched toeach job's experimental file by naming convention (`compare-batch`).A CLI and a Python API: every stage (`generate`/`run`/`validate`/`pipeline`/`compare`/`compare-batch`) is a subcommand, and everyunderlying function is also importable directly.Repository aboveInstallation```bashgit clone https://github.com/KumudithaRathnayake/fdmnes-xas-pipeline.gitcd fdmnes-xas-pipelinepip install -e .            # core package -- no third-party dependenciespip install -e ".[plot]"    # + matplotlib, for compare/compare-batch --plotpip install -e ".[dev]"     # + pytest, to run the test suite```(Or just add the repo root to `PYTHONPATH` -- `fdmnes_pipeline/` is plainPython with no build step required.)FDMNES itself is not included in this repository and is notredistributed by it. FDMNES is developed and distributed by InstitutNéel (CNRS); download the appropriate build for your platform from itsofficial site and get your own license/access per their terms. This package never hard-codes a path to it --every command takes the executable's location as the `--executable`argument, so nothing needs to change in the code itself:```bashexport FDMNES_BIN=/path/to/your/fdmnes_linux64   # wherever you installed itpython3 -m fdmnes_pipeline.cli run --config examples/jobs.json --executable "$FDMNES_BIN"```Quick startThe example structures under `examples/structures/` are synthetic,invented placeholders (see `examples/README.md`) chosen only so thesethree steps run immediately, with no external data needed.Generate the FDMNES input files for the bundled demo jobs (both theK-edge/CIF example and the L-edge/XYZ example):```bash   python3 -m fdmnes_pipeline.cli generate --config examples/jobs.json   python3 -m fdmnes_pipeline.cli generate --config examples/jobs_ledge.json   ```Run FDMNES on a generated input, once you have FDMNES installedsomewhere (see Installation above) -- or use `pipeline` to generate +run + validate in one step:```bash   python3 -m fdmnes_pipeline.cli pipeline \       --config examples/jobs.json --executable "$FDMNES_BIN" --timeout 7200   ```Compare the computed spectrum against an experimental one (onceyou have both a `_conv.txt` and an experimental file, e.g. named`Demo_Ni_MO6_FDM_EXP.txt` alongside it):```bash   python3 -m fdmnes_pipeline.cli compare-batch \       --config examples/jobs.json --summary-csv batch_summary.csv   ```Settings (`ProtocolSettings` / `AbsorberSettings`)Setting	Meaning`radius`	FDMNES cluster radius (Å) around the absorber`energy_range`	FDMNES `Range` keyword string (grid + step sizes)`use_green`, `use_pbe96`, `use_scf`, `use_quadrupole`, `use_convolution`	On/off FDMNES keywords (`Green`, `PBE96`, `SCF`, `Quadrupole`, `Convolution`)`use_tddft`, `use_spinorbit`, `vmax`, `estart`, `overad`	L-edge-only extras (`TDDFT`, `Spinorbit`, `Vmax`, `Estart`, `Overad`); no-ops unless a job sets `edge``absorber_mode` / `absorber_index`	`"all"` (every atom of that element, FDMNES's `Z_absorber`) vs. a specific site index/indices (FDMNES's `Absorber`) -- use the latter to simulate each distinct metal environment in a structure separately`edge`	e.g. `"L23"`; omit for the default K edgeHow it works`input_generator.build_fdmnes_input` is a direct, line-for-line port ofthe original hand-written FDMNES input text (same keyword order, sameformatting), now driven by a typed `JobSpec`/`ProtocolSettings` instead ofhand-edited per structure. `runner.FdmnesRunner` wraps the actual FDMNESsubprocess call: it writes `fdmfile.txt` next to the executable (FDMNESreads the input file path from there, not from a command-line argument),launches FDMNES (optionally under `mpirun`), and records whether itlaunched, its return code, and whether it timed out. `validation.py` theninspects the resulting files -- `fdmnes_error.txt`, the `_bav.txt` log,and the `_conv.txt` convoluted spectrum -- against the conventionsdescribed in FDMNES's own manual, rather than parsing output for aspecific research result. `comparison.py` is independent of all of that:given any two text files (a computed spectrum and an experimental one),it normalizes both to a 1.0 maximum, aligns them on energy (automatically,by peak position, or with a shift you supply), interpolates them onto ashared grid, and reports the Pearson correlation coefficient and R-factor-- the same non-machine-learning benchmarking protocol used in Chen etal., Chem. Mater. 2024, 36, 2304-2313, Figure 4.OutputsStage	Output`generate`	`<input_file>` -- the FDMNES input text`run`	FDMNES's own `<filout>_bav.txt`, `<filout>.txt`, `<filout>_conv.txt` (if `Convolution` was requested)`validate`	A printed `job_name -> SUCCESS/WARNING/FAILED` table (`report_table`)`compare`	Printed Pearson r / R-factor / shift; optional `--output-csv` (aligned, normalized spectra + metrics) and `--plot` (overlay PNG, needs matplotlib)`compare-batch`	The same, per job, saved next to each job's own `_conv.txt`; optional `--summary-csv` with one row per jobValidationThe test suite (`pytest`, 84 tests, all passing, no FDMNES binaryrequired) includes two kinds of known-answer checks on public/syntheticdata:Input-format regression tests: generating an input file for aknown structure and settings reproduces the exact expected FDMNESkeyword text byte-for-byte -- for both the K-edge/CIF `Cif_file` branchand the L-edge/XYZ `Molecule` branch (atom coordinates, formatting, andall 19 atoms of the synthetic demo molecule round-tripping exactlythrough `parse_xyz` -> `build_fdmnes_input`).Comparison-logic known-answer tests: given two synthetic Gaussian"spectra" with a known energy offset (e.g. a peak shifted by exactly2.0 eV) and a known intensity scale difference, `align_and_normalize`recovers that exact shift and the resulting Pearson correlation is`> 0.999` -- confirming the alignment and scoring logic itself iscorrect, independently of any real measurement.A separate fake-executable test harness (`tests/conftest.py`) exercises`FdmnesRunner` against a real subprocess launch (argument parsing,`fdmfile.txt` placement, timeout handling, non-zero exit codes) withoutneeding the real FDMNES binary.Limitations and roadmapFDMNES itself must be installed separately; this package onlygenerates its input, launches it, and interprets its output.`compare`/`compare-batch` score the whole fitted energy range with asingle Pearson r/R-factor; region-weighted scoring (pre-edge,rising-edge, white-line, post-edge windows scored separately) is notbuilt yet.The L-edge `Molecule` branch currently expects a single isolatedmolecule per job; periodic molecular crystals would need a CIF-basedjob instead.No GUI -- this is a CLI/library by design, meant to sit on top ofwhatever job-submission setup (tmux, a cluster scheduler, …) youalready use.Saves roughly 54 minutes per structure of bookkeeping (writinginput files by hand, launching runs, and re-checking output files)compared with doing the same steps manually; FDMNES's own compute timeis unchanged either way.AuthorKumuditha Rathnayake -- University of Illinois Chicago (UIC)GitHub: github.com/KumudithaRathnayakeWebsite: kumuditharathnayake.github.ioLinkedIn: www.linkedin.com/in/kumuditha-rathnayake-126602103ORCID: https://orcid.org/0000-0002-7591-5630
